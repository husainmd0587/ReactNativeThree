2. THE LOOP (what happens when the user taps "Upgrade")
--------------------------------------------------------------------------------
 1. Client: initConnection + getProducts({skus:["engineering_premium"]})
    -> shows Play-localized price (fallback label: Rs.299 lifetime).
 2. User taps Buy -> requestPurchase (Android: {skus:[...]}, iOS: {sku}).
 3. Play Billing sheet completes -> client gets purchaseToken.
 4. Client: POST https://www.techt.site/api/content/billing/google/verify-purchase
    Authorization: Bearer <accessToken>
    body: {productId, purchaseToken, packageName:"com.threeapp"}
 5. BACKEND (server-side, source of truth): verifies purchaseToken against
    Google Play Developer API (androidpublisher v3) using a SERVICE ACCOUNT
    that never leaves the server.
      - purchaseState must be 0 ("purchased") or the request is rejected
        (409 PURCHASE_PENDING / PURCHASE_NOT_ENTITLED, 400 PURCHASE_INVALID).
      - On success: upsert into three3d_purchases + set
        User3dApp.premium.active = true.
      - Responds: 200 {success:true, data:{purchase, premium:{active:true}}}.
 6. Client on 200: finishTransaction({purchase, isConsumable:false}) ->
    purchase acknowledged in Play.
 7. Client refetches GET /auth/me -> backendUser.premium.active is true ->
    profile shows the existing Premium row as active AND the upgrade card
    flips to "Lifetime Premium active".
 8. Client on verify failure: finishTransaction is NOT called, so the
    purchase stays unacknowledged and Google redelivers it later — the money
    is never lost. NO premium is granted until /auth/me confirms it.

Failure mapping the client understands:
  501/404 VERIFY_NOT_CONFIGURED -> "verification not available, purchase kept"
  502 GOOGLE_UNREACHABLE / GOOGLE_AUTH_ERROR -> retryable / contact support
  400/409 -> rejected purchase states
  E_USER_CANCELLED -> silent (user closed the sheet)
  E_ALREADY_OWNED -> treated as owned, runs restore/verify path

6. REMAINING MANUAL STEPS BEFORE GO-LIVE  (in order)
--------------------------------------------------------------------------------
 a) PLAY CONSOLE: create non-consumable product "engineering_premium",
    price Rs.299 in India, activate it. Add license testers
    (Settings -> License testing). Upload a signed build:
      cd android && ./gradlew assemblePlayRelease
    (needs MYAPP_UPLOAD_* keystore props — none are stored in the repo).
 b) GOOGLE CLOUD / PLAY: enable "Google Play Android Developer API";
    create or pick a service account (Play Console -> Settings -> API access
    -> grant it access to package com.threeapp); download its JSON key.
 c) SERVER: set GOOGLE_SERVICE_ACCOUNT_JSON=<that JSON> (or
    GOOGLE_APPLICATION_CREDENTIALS=/path/on/server.json) on techt.site,
    deploy commit 6fd5a53 of the express repo, restart.
 d) DEVICE E2E: install the Play-installed build (billing needs real Play,
    adb-installed debug builds return item-unavailable for unlisted builds),
    buy with a license-tester account -> profile must show the green active
    box -> Play Console shows the order -> server three3d_purchases has the
    row. Then refund in Play Console and confirm /auth/me no longer grants.
 e) SECURITY (already designed in, do not undo): service-account JSON stays
    server-side only; the app only ever sends purchaseToken; entitlement is
    only ever granted from the backend, never from a client flag.

7. HOW TO RUN / TEST LOCALLY
--------------------------------------------------------------------------------
 App (device connected over USB):
   npx react-native start --reset-cache          (Metro, port 8081)
   npx react-native run-android --mode=playDebug
   adb shell am start -n com.threeapp/.MainActivity
   Profile tab -> upgrade card is under the Premium status row.
 Backend (needs Redis + Mongo + .env):
   node index.js
   curl -X POST http://localhost:8000/api/content/billing/google/verify-purchase \
     -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
     -d '{"productId":"engineering_premium","purchaseToken":"..."}'
   Expected without server credentials: HTTP 501 VERIFY_NOT_CONFIGURED.
