--------------------------------------------------------------------------------
ROOT CAUSE
--------------------------------------------------------------------------------

react-android:0.76.3 and hermes-android:0.76.3 ship prebuilt native binaries
whose ELF LOAD segments are aligned to 4 KB (align 2**12).

Google Play requires 16 KB (align 2**14) compatible native libraries.

This is the same underlying React Native 0.76-era problem previously
experienced in the "Minnu Zaika" application. No other dependency audit was
required to reach this conclusion.

The upgrade target is React Native 0.77.x, whose prebuilt binaries are already
16 KB aligned.

Interpretation:
  align 2**12  ->  4 KB   ->  NOT 16 KB page-size compatible
  align 2**14  -> 16 KB   ->  16 KB page-size compatible

The 0.77.0 AARs were already present in the local Gradle cache, so the
remediation was proven at the binary level without performing any build.

Phase 4 (Skia / Reanimated inspection) was intentionally SKIPPED. The decision
tree terminates at RESULT A, so auditing further dependencies would only have
consumed time without changing the conclusion.

This is the NDK that FAILED. It must be reverted to the project's known-good

NDK 28 is NOT the automatic solution. Under RN 0.76.3 it produced the

originating from RN 0.76.3 Folly headers (folly/Traits.h, folly/Range.h).

NDK 26.1.10909125 remains the correct choice after the RN upgrade as well,
because RN 0.77's prebuilt libraries are already 16 KB aligned. The NDK version
is independent of the 16 KB requirement for prebuilt binaries.


--------------------------------------------------------------------------------
SECONDARY BLOCKER IDENTIFIED (not yet fixed)
--------------------------------------------------------------------------------

The application has its own CMake native build:

  android/app/build.gradle:
      externalNativeBuild { cmake { path "src/main/cpp/CMakeLists.txt" } }

  android/app/src/main/cpp/CMakeLists.txt:
      builds SHARED library "native-lib" from native-lib.cpp
      plus the local "manifold" submodule (STATIC)
      compiler flags: -O3 -fvisibility=hidden -fPIC
      NO page-size linker flag is set

A CMake-built shared library defaults to 4 KB segment alignment. Therefore
libnative-lib.so will remain a 16 KB incompatible binary IN THE FINAL APK even
after the React Native upgrade, unless it is addressed.

Minimum fix (one line added to CMakeLists.txt):

  target_link_options(native-lib PRIVATE "-Wl,-z,max-page-size=16384")

This is independent of the RN upgrade and would otherwise have surfaced only
during final artifact verification.
